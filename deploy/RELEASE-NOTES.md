## 更新内容（0.4.14）

### 缺陷：真实回退入口把「任务摘要」当完整档判回退资格

作者 2.7.0 的回退入口 `round-history.js:551-565` 经 `chats.readState`（＝`taskStateReader.read`）读档，
而 `taskStateFields` **不含** `timeline.checkpoints`` 与 `messages`。而我方在取得完整权威档**之前**，
就用这枚摘要调 `latestSendRecord` 判断「是否最新发送 / 是否带前像 / 操作身份是否一致」。

摘要里没有 checkpoint ⇒ 判不出基准 ⇒ 抛「回退目标不是当前最新发送」。

**表现**：页面能看到并点击回退目标，执行端却必定失败——按钮可点，一点就报错。

### 修复

- 入口预检**只保留身份与分支**（`chatId` / `sessionId` / `branchId`，这是不删错档的底线），
  删除三道用摘要判资格的门：`latestSendRecord(chat,{})` 的「回退目标不是当前最新发送」、
  「回退操作身份已变化」、停止任务后的「最新发送已变化，拒绝旧回退」。
- **原生输入锚点归属校验保留**（确认发起凭据的锚点仍属于该轮输入，防删错数据），改为无条件执行，
  不因删掉资格门而连带丢失。
- 轮次与基准一律以**取得完整权威档与真实 Session 之后**的读数为准：
  `chat = await readChat(chat.id)` 之后，再由权威事件流的 `turn/start` 推导目标轮。

### 未改动的既有安全负例（全部保留并经定向复验）

- 缺业务前像仍**响亮拒绝**：`最新发送缺少完整发轮前基准，未删除任何数据`。
- `basedOn.branchId` 指向其它分支的账本节点仍拒，不删跨分支残留。
- 失败清理路径（`failureTarget`）的缺基准拒绝语义不变。
- 数字旧入口显式指定非最新轮仍拒：`回退目标已经变化，请刷新确认`。
- 并发静止、物理纯尾单事务、CAS、后置回读、同连接同步均未削弱。

### 关于「只删正文、变量不恢复」的降级方案

本轮曾按「任何形态都要能回退到上一轮」做过 synthetic 兜底：无业务前像时仍删尾、变量不猜不恢复、
回执标 `baselineMissing`。但该方案与 0.4.12 起确立的「缺前像时不猜、响亮拒绝」安全立场冲突，
且会削弱 8 处既有安全负例（失败清理缺基准拒绝、异分支前像拒签、纯原生尾交 native-only 协议等），
**已整体回退**。最终只修「用错数据」这一处根因——资格判断改用完整权威档，而不是放宽判断标准。
