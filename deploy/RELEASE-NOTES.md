# 0.4.24 stable：正文重新生成、结算与同步重试修复

## 目标版本

延续DSH Tavern **stable 2.7.0**、提交 `9603eca4f854b55980b632a691a0d8aec900a49a` 与 **DSH0.1.5-rc.2代/peer <0.2.0** 的既有适配范围。本次正文编排及source/built接缝另在既有作者 `a390af170cfe5ed3e9213a2801cbcce321e2008b` 程序副本上精确验证。

不是main3.0/DSH0.2兼容版，不与另一同名V2源码线共装；其他未适配版本可能运行报错。

## 本版修复

- 本次0.4.24同号重打包新增 `76513ba` 变量注入修复（`fa7af6b`审查）：重生成首步由原变量变化生产者退役本轮旧输入，再沿作者逻辑写当前变化；无变化也撤旧值。既有SQLite纯尾采用物理删除旧输入及空退役，前轮变量历史和独立模型通知保留。不新增通用分类器、名单、预检或运行校验层。
- 同时包含 `f5f47ec` 及前序修复：SQL从原玩家输入后换尾，消费作者已算的替换/清理与真实当前消息面，独立通知保留，旧尝试frame及工具输出不累计。不恢复插件名/来源/输出白名单、分类准入或重复预检。
- 增量快照内容未变、不重新注入时，继续保留当前有效世界书与人物卡提示；系统提示正常替换带回真实引用依赖，只省略已删目标上的空退役。系统更新、同值沿用及主动清空不会回到早期提示。有效请求头/请求上下文延续最后值，不搬历次旧请求。

- 原玩家输入所在步骤与新正文首步接续，后续多步编号及引用一起映射，避免重复step/start使页面组装失败。
- 采用新正文后，保原作者完整结算周期：按原轮before变量基准重算，再发送当前状态的同连接同步。
- 完成凭据不再被后续正常结算推进revision误判过期；新生成只恢复实际未完成意图。
- 首次发送前保本次operationId；广播失败或响应丢失后，再点只恢复/同步本次结果，不重新生成/结算；尚未采用的请求明确报错，不拿旧成功冒充。
- 按钮直接等待同步，既有8秒超时覆盖挂起消息重读；失败重试读取当前状态，同一回执再到只重读消息，不把旧队列/任务/运行状态盖回。

此前快照/系统替换修复最终9条不同受影响精确叶通过：两条原审查失败用例补真实SQLite事务换尾/冷Session，并覆盖三次快照沿用、旧frame不累计及系统主动清空；另七条覆盖独立通知、工具链删除、引用/必要负例和真实作者编排/热冷UI组装。其余主链与失败重试按未变范围复用既有证据，未跑全量或重跑未变断言。两类专门输入不代表完整按钮链；变量结算是确定性adapter，不是真实模型/MVU执行器或浏览器整页验收。
