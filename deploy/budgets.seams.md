# 数字型预算的薄缝（部署件）—— host 侧 2 项

> 配套模块：`dsh-tavern-storage-sqlite-v2/lib/budgets.js`（`BUDGETS.scriptClaimMs` / `BUDGETS.serverTemplateMs`）
>
> ⚠ **先读这句**：把数字收进我们包**不消除缝** —— 作者文件仍要被改一行去读它。收益是**单一来源、一处可审**；
> 2026-10-01标准链现由 [核心预算转换](<core-host-transform.mjs>)经 [统一apply/check/uninstall](<standard-seams.mjs>)自动覆盖两处Host消费者，不再依赖手工补丁①。受支持新进程import前完成；未知版本/漂移拒绝覆旧备份，现场尚未部署。下面是原始接线规格，不代完整标准ready/行为验收。

## 1. `lib/domain/tavern-script-dispatch.js`（① 租约）

上游原文（补丁脚本 ① 的锚点，正则是 `TAVERN_SCRIPT_CLAIM_TIMEOUT_MS = (\d+)`）：

```js
const TAVERN_SCRIPT_CLAIM_TIMEOUT_MS = 30000
```

缝（两步）：
```js
import { BUDGETS } from 'dsh-tavern-storage-sqlite-v2/budgets'   // 顶部加一行
...
const TAVERN_SCRIPT_CLAIM_TIMEOUT_MS = BUDGETS.scriptClaimMs   // 原 30000
```

## 2. `lib/domain/server-template-runtime.js`（服务端模板预算）

上游原文（补丁脚本锚点 `timeoutMs = 120000`）：

```js
  ... timeoutMs = 120000 ...
```

缝（两步）：
```js
import { BUDGETS } from 'dsh-tavern-storage-sqlite-v2/budgets'   // 顶部加一行
...
  ... timeoutMs = BUDGETS.serverTemplateMs ...                // 原 120000
```

## 3. 为什么**另外三项**不在这里

| 项 | 位置 | 为什么留字面补丁 |
|---|---|---|
| ③ 客户端 MVU 下载超时 `options.timeoutMs \|\| 10000` → 60000、重试 2→3 | `lib/client.js` | **构建产物**（首行 "Generated by pnpm build:client; do not edit directly."）⇒ 浏览器 bundle 无法 import 本包 |
| ⑤ 客户端预算放宽（初始化 `timeoutMs = 120000` 一族） | `lib/client.js` | 同上 |
| ⑭ 开场预览 `type === 'dsh-tavern-helper-call' ? 300000 : 10000` → 60000 | `lib/client.js` | 同上 |

⇒ 这三项**只能**由补丁链的字面替换承担；若将来客户端侧要做成"预算集中"，正确路径是让**上游**把这些值提升为可配置项（或走 `dsh.client.external` 解析我们的包 —— 但那是构建期的事，不是运行期替换）。

## 4. 部署后验证

1. `dsh --profile tavern --dump-config | grep -n 'dsh-tavern-storage-sqlite-v2'` ⇒ 我们的 row 在位；
2. `grep -rn "BUDGETS\." <tavern-plugin>/lib/domain/tavern-script-dispatch.js <tavern-plugin>/lib/domain/server-template-runtime.js` ⇒ 两处都在读我们的常量；
3. 行为回归：卡脚本租约不再 30s 超时（跑一次长结算）；大卡服务端模板准备不再 120s 掐断。
