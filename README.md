# DSH Tavern SQLite V2

**让长对话存档少做重复读写，让剧情回退真正清掉被撤销的尾部——MVU与角色卡脚本在服务端执行，不占浏览器。**

这是面向DSH Tavern的SQLite存储与服务端执行插件：聊天、会话事件和MVU变量历史改用数据库管理，提供增量写入、按需读取、独立存档分叉与干净回退。**V2在存储与状态一致性之上，把MVU结算、角色卡脚本VM/ESM与Helper生成搬进服务端进程执行，浏览器只负责界面。**

## 功能亮点

| 特点 | 为你解决什么问题 |
|---|---|
| **服务端MVU与卡脚本执行** | MVU结算、卡脚本VM/ESM模块、Helper生成在服务端运行，不依赖浏览器在线且就绪；关掉浏览器也能完成结算，重开页面不重跑脚本。 |
| **SQLite增量存档** | 按聊天头字段、消息楼层拆分存储；普通局部更新只序列化、写入变化的部分，不因追加一楼就重写全部历史。会话事件使用SQLite事务与WAL管理。 |
| **历史按需读取** | 消息窗口、指定楼层和结算检查点按范围读取；后台配置只取所需头字段，场景读取只取显示相关字段。访问哪楼才生成哪楼的独立副本。 |
| **MVU变量历史瘦身** | 聊天与变量快照共用同一数据库连接、同一写事务，避免双库双写。旧变量树先归档再从热状态移出，近期楼层保留热窗口；查看旧楼时按楼层和swipe补回，重复补数走缓存。 |
| **真正的物理尾部回退** | 不只是隐藏气泡：直接截断被撤销的会话事件尾部，回拨事件计数、运行轮次和写句柄，重建内存投影并清理目标轮缓存与运行痕迹。 |
| **前后台同步恢复** | 回退后通过现有连接同步受影响会话的状态、队列与任务基线；阻止旧任务、旧浏览器租约和迟到写回把被删剧情重新写回来。 |
| **原档保留，独立分叉继续玩** | 旧存档保持只读；你在面板点击「分叉迁移到数据库存档」，创建新的聊天和原生会话身份，在SQLite分叉中继续，源档与源链接保持不变。 |
| **一条命令安装／卸载** | 复制命令即可安装，无需手动下载插件包或填写版本号；卸载也只需一条命令，存档保留。 |

### 优化为什么不止是"换个数据库"？

- **少写**：头字段与楼层分开更新，未变化的内容不重复序列化落库；内部整理后的最终写集直接提交，不再重复全档比较。
- **少读、少复制**：按需投影＋带容量上限的缓存；显示、后台配置、结算分别取各自需要的数据，变量快照补数命中缓存不再重复解析。
- **变量与正文一起提交**：同库同事务，变量归档失败时整笔聊天写入回滚，避免正文已保存、变量却没跟上的半态。
- **回退到真正一致的状态**：除了正文和游戏变量，还处理原生轮号、任务、派生投影、世界书投递缓存和旧写入生命周期，减少旧轮残留继续影响后续剧情的机会。

这些是已实现的优化机制，不代表每个读取接口都是常数成本：冷读、新revision和显式全量读取仍可能处理整段历史。当前公开V2没有统一的页面性能基准，因此不标注未经本代实测的"快几倍／省多少内存"。

## 一键安装

已有兼容CLI酒馆时，直接执行；无需在命令里填写版本或目录：

```sh
curl -fsSL https://raw.githubusercontent.com/huajiao1998/dsh-tavern-sqlite-v2/main/install.sh | sh
```

systemd 实例首次安装（安装器自动补启动参数、自动清理旧代残留，装完即用）：

```sh
curl -fsSL https://raw.githubusercontent.com/huajiao1998/dsh-tavern-sqlite-v2/main/install.sh | sh -s -- install --home /酒馆目录 --systemd-unit 酒馆服务.service --prepare-env
```

根目录[install.sh](<install.sh>)自动获取最新正式发行安装器。它会从`DSH_TAVERN_CLI_HOME`、`DSH_HOME`、当前目录和`~/.dsh-tavern`识别酒馆；找不到或有多个时才需要`--home`明确选择。安装前请备份并停止页面交互。

详细参数、本地离线安装、预检与失败恢复见[安装说明](<deploy/INSTALL.md>)。

**Windows（桌面版 / CLI）**：从 [Releases](https://github.com/huajiao1998/dsh-tavern-sqlite-v2/releases/latest) 下载 `-win.zip`，先与同页 `SHA256SUMS` 对照校验（PowerShell：`(Get-FileHash .\dsh-tavern-sqlite-v2-0.2.3-win.zip -Algorithm SHA256).Hash` 应与同名行一致），再按以下步骤安装：

1. 把 zip 解压到酒馆目录内任意一层（例如 `D:\Program Files (x86)\DSH-Tavern\`），会得到 `…\DSH-Tavern\dsh-tavern-sqlite-v2\`；
2. 右键其中的 `install.ps1` →「使用 PowerShell 运行」进入菜单（安装 / 更新 / 卸载 / 只读预检）；也支持命令行：`.\install.ps1 install|update|uninstall|check`；
3. 桌面版安装/卸载前请从托盘**完全退出**酒馆，完成后重新启动生效；本机未装 Node 时安装器可复用桌面版自带运行时；`update` 仅下载官方资产并校验后先卸旧再装新。

**0.2.3 Windows 支持与重结算修复**：卡脚本 VM/ESM 在 Windows 桌面版经 Worker 线程执行（Linux/CLI 仍走原进程内路径，能力驱动分叉）；修复候选任务推进剧情版本后重结算永久「变量结算中…」的问题——新结算只绑定同版本正文轮次，跨版本重试走作者独立结算路径，提交护栏与身份校验不放宽。维护入口支持「退出撤缝态」：酒馆正常退出后再执行一键更新/装卸不再报缺恢复记录。

**0.2.2 上游适配**：适配作者 v2.5 晚间重发布树（实测至 `9e9b26d`，含压缩重写、台账手动化、卡片工作台、MVU `$meta` 修复等 50+ 提交）。全部标准接缝锚点在新树上逐一验证通过，v2.5 首发线旧树继续兼容。升级酒馆后请按「卸载与更新」一节先卸载旧代、再安装本版。

**0.2.1 装卸修复**：不再从当前缝合态重建作者前像。旧记录损坏时，一键维护器自动验证自身留下的洁净安装证据，副本重放必须与全部当前活动源码逐字节一致，才允许恢复；不修改 after 哈希放过真实漂移。同版 install 可只修复元数据，uninstall 可直接完成恢复后卸载。`uninstall --check` 仅诊断、不改目标。没有可靠材料则保留现场并明确拒绝，存档与数据库不动。

## 原档怎么继续使用？

1. 安装后打开旧存档，以只读方式查看。
2. 在酒馆状态面板点击**「分叉迁移到数据库存档」**。
3. 在新创建的SQLite分叉中继续对话和回退；旧档不被自动转换或覆盖。

剧情回退针对本档的正文、游戏变量、进度和被撤销轮的运行数据；**人物卡／世界书资源库原件与独立手工编辑不会跟着剧情回退撤销。**

## 卸载与更新

```sh
curl -fsSL https://raw.githubusercontent.com/huajiao1998/dsh-tavern-sqlite-v2/main/install.sh | sh -s -- uninstall
```

卸载保留原档和数据库存档，不把SQLite存档转换回JSON。当前升级方式为先卸载旧代，再使用新发行包安装；重复执行安装不会静默升级。

用户入口地址长期不变，新版本由最新正式Release提供；只推送main源码不会自动发布安装包。每份正式SH锁定同次发行包与SHA256，避免混装。更新详情见[更新日志](<CHANGELOG.md>)。

## 兼容与使用须知

- 当前适配**作者DSH Tavern 2.5.0（v2.5 首发与重发布树均实测，最新至 `9e9b26d`）、DSH／boot 0.1.5-rc.2**，需要既有Node22.19+、pnpm与CLI tavern profile；安装器面向Linux、macOS、WSL2与Windows（桌面版/CLI）。
- **无需手工预配`--experimental-vm-modules`**：安装命令加`--prepare-env`，安装器自动把它补进systemd单元（备份原配置、按原方式重启复验、失败自动回滚），**安装完成后服务启动自带该参数**。不加该开关则要求该参数已存在（默认不改动你的启动配置，缺失时停服前明确拒绝）。
- **与V1互斥**：同一实例不能同时安装V1与V2；已装V1时先用V1安装器完整卸载，再安装V2。V1卸载可能留下旧维护备份文件——安装时同样加`--prepare-env`即可自动隔离（只移动到维护证据目录，不删除；不带该开关则列清单明确拒绝）。
- 装卸走目标profile的官方离线包管理入口，不执行生命周期脚本、不联网补依赖；json5、jsonrepair、lodash、yaml须在既有离线依赖材料中可用。
- V2的MVU／卡脚本在服务端执行；这是V1（浏览器执行版）的服务端版本线，两者按需选用。
- 安装器的60秒预算从插件包就绪后开始，失败恢复可能更久。源码级装配与恢复已在固定源码副本上验证；安装后请登录刷新，确认历史、只读状态、手动分叉及回退，真实页面整轮表现以你的环境实测为准。
